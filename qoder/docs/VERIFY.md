## 二、样例 1：从零初始化（可重复执行）

**输入**

```bash
python db/init.py
```

**第一次预期输出**

```
schema      : 3 statements applied (CREATE TABLE IF NOT EXISTS)
questions   : imported 21 rows -> now 21
ref_point   : now 85 rows
answer_log  : now 0 rows
```

**再执行一次（幂等验证）** —— 行数必须完全相同，不能翻倍：

```
questions   : imported 21 rows -> now 21
ref_point   : now 85 rows
```

**seekdb 在这里做了什么**：`CREATE TABLE` 建了三张表，其中 `questions.keywords` 与
`ref_point.content` 各带一个 `FULLTEXT INDEX ... WITH PARSER ik`，保证中文按词切而不是按字切。

⚠️ 首次执行后 `.data/seekdb.db` 会占约 **330 MB**（seekdb 会把 `seekdb.exe` 拷进数据目录，
另有预分配的 redo log）。磁盘紧的机器先看一眼空间。

## 三、样例 2：中文全文检索真的在起作用

这是本项目的核心 —— 「找同类题」。下面每条 SQL 都可以直接在 `db/check.py` 或任意
seekdb 客户端里跑。

### 3.1 检索「回表」

```sql
SELECT id, MATCH(keywords) AGAINST('回表 覆盖索引') AS rel
FROM questions
WHERE MATCH(keywords) AGAINST('回表 覆盖索引')
ORDER BY rel DESC;
```

**实际命中（未剪枝）**

```
题2  rel=7.4092   什么是回表？为什么说「覆盖索引能避免回表」？
题20 rel=4.4649   索引下推（ICP）是什么？它省掉了什么开销？
题1  rel=1.6993   什么情况下 MySQL 的索引会失效？
题13 rel=1.3186   最左前缀原则是什么？
题7  rel=1.0961   聚簇索引和二级索引的区别？
```

**按 0.3 相对阈值剪枝**（阈值 = 7.4092 × 0.3 = 2.2228）：

```
保留：题2（7.41）、题20（4.46）     ← 都是索引族，正确
剪掉：题1（1.70）、题13（1.32）、题7（1.10）
```

### 3.2 检索「隔离级别 幻读」

```sql
SELECT id, MATCH(keywords) AGAINST('隔离级别 幻读') AS rel
FROM questions
WHERE MATCH(keywords) AGAINST('隔离级别 幻读') ORDER BY rel DESC;
```

**实际命中**：`题3 rel=8.9868`、`题8 rel=1.5...`（共 2 行，全部保留，都是事务族）

### 3.3 九组检索的整体结果

`demo/queries.json` 里存了 9 组口语化提问的真实执行记录（含完整 SQL 与分数），
这些数据会被站点原样回放。摘要：

| 用户输入 | 实际查询词 | 剪枝后保留 | 是否同族 |
|---|---|---|---|
| 这个查询怎么突然变慢了，加了索引也没用 | 慢查询 索引失效 | 6, 13, 1, 12 | ✓ 全是排查/索引 |
| 明明建了索引为什么还是全表扫描 | 索引失效 | 13, 1, 2, 7 | ✓ |
| 面试官问我回表是什么，我答不上来 | 回表 覆盖索引 | 2, 20 | ✓ |
| 事务隔离级别到底几级，幻读是什么 | 隔离级别 幻读 | 3, 8 | ✓ |
| 主从延迟导致刚写的数据读不到 | 主从复制 延迟 一致性 | 18, 9 | ✓ |
| 表太大了要分库分表，分片键怎么挑 | 分库分表 分片键 | 17, 10 | ✓ |
| 应用一直报连接超时，连接数打满 | 连接池 连接数 连接超时 | 21, 11 | ✓ |
| redo log 和 binlog 有什么区别 | redo log binlog | 5, 19 | ✓ |
| 这个 SQL 为什么要回表两次 | 回表 索引下推 | 20, 2 | ✓ |

### 3.4 整体质量：同族命中率 20/21 = 95%

判据（客观，不靠人工感觉）：对每道题用它自己的 `keywords` 去检索，
**top1 与查询题的 `tags` 有交集即算命中**。

唯一未命中的是题 16（长事务）→ 题 19（崩溃恢复），两者其实都讲 `undo log`，
只是没打同一个 tag。逐题明细可用 `_ratio_scan` 类脚本复现，详见第五节。

## 四、样例 3：记忆真的落盘了（关库重开）

**输入**

```bash
python db/check.py
```

**关键读数**

1. 写入两次作答（35 分、72 分）后，`current_score(题2)`：
   ```
   score=72   attempt_no=2
   ```
2. **父进程 close 掉数据库、由全新子进程重开同一目录**再查：
   ```
   [子进程] score=72  attempt_no=8  answered_at=2026-10-29 12:37:11
   ```
   （`attempt_no` 是 8 而不是 2，是因为这份库被 `check.py` 反复跑过，历史累加。
   **重点不是数字，而是「全新进程读到了父进程写进去的数据」**。）
3. 该题全部作答记录按 `attempt_no` 递增，`score` 与最后一次一致。

**结论**：数据不是内存里的假象，是真的写进了 seekdb 的存储文件。

## 五、样例 4：接口层自测

**输入**

```bash
python server/selftest.py
```

**预期输出（结尾）**

```
[3.5] 产品口径断言（不是只看 200）
[OK ] 点评输出严格三段且不超过 120 字
[OK ] 响应与入库点评里没有任何密钥
[OK ] stats 报出点评引擎（只有模型名，没有 Key）
[OK ] 相似题走全文而不是兜底
[OK ] 下一题是相似且没练过的题
[OK ] 答差的那道题进了错题本
[OK ] 今日进度随作答变化

结果：14 个接口 + 7 条产品断言，失败 0 项
```

这 7 条不是「状态码 200 就算过」，而是检查**产品口径**：

- `相似题走全文而不是兜底`：返回体的 `how` 必须是 `fulltext`，且每行 `rel > 0`
- `下一题是相似且没练过的题`：`via == similar` 且 `attempt_no == 0`
- `答差的那道题进了错题本`：错题本里必须包含题 2
- `点评输出严格三段且不超过 120 字`：三段前缀齐全，整段长度 ≤ 120

另外还有两条安全断言：

```
[OK ] 404  GET /api/submit 不存在的题（必须被挡）
[OK ] 404  GET /../../../windows/win.ini（路径穿越）
```

**输入**


**三组实际读数**

| 组 | 环境 | engine | 结果 |
|---|---|---|---|
| A | 配了真实 Key | `model:deepseek-chat` | 三段齐全，长度恰好 120 字（卡在上限） |

## 七、seekdb 相关的两个已知行为（不是 bug，别误判）

### 7.1 ik 分词对技术词退化成单字

`AGAINST('回表')` 与 `AGAINST('表')` 的返回分数**逐位相同**：

```
题2：1.8681573701991185    题10：1.191390926655287
```

说明「回表」被切成单字「表」。所以搜「回表」会连带召回「分库分**表**」的题（分数低，被 0.3 阈值剪掉）。

**本项目的对策**：检索字段只用人工维护的 `keywords` 列，不用题干（题干里「查询」「表」
这类字太密，噪声不可控），再加 0.3 相对阈值剪枝。

### 7.2 `IN BOOLEAN MODE` 不可用

```
AGAINST('回表' IN BOOLEAN MODE)  -> 静默返回 0 行，不报错
AGAINST('"回表"')                -> 结果与不加引号完全一致（引号被忽略）
```

所以不要指望用 BOOLEAN MODE 做精确匹配。

### 7.3 50% 停用词阈值（已检查，当前未触发）

MySQL 系全文检索会把「出现在超过 50% 行里」的词当停用词忽略。
`db/check.py` 的 e) 段会统计：**词表 73 个词，最高覆盖率 19%（`log` / `undo` / `查询` 各 4/21 行），
无词超过 50%**。以后扩题库要重跑这条。

## 八、排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `No matching distribution found for pylibseekdb` | 清华源没有这个包 | 换阿里云/中科大/腾讯源 |
| `pylibseekdb.__version__` 报 AttributeError | 这个包没有该属性 | 用 `importlib.metadata.version("pylibseekdb")` |
| 检索结果偏多 | 词太泛（如「查询」） | 属正常，靠 0.3 阈值剪枝 |
| `.data` 占了 1 GB+ | 跑过 `check.py` / `selftest.py`，各建了一个独立库 | 删掉不需要的 `.data/_check`、`.data/selftest.db` |
| 端口被占 | 8765 被别的进程用了 | `python server/app.py --port 8790` |
